Claude Code controls OpenApe Pods

Connect once, then list, inspect, create, edit and control Pods from Claude Code. Browser and desktop show the same committed changes.

Purpose and scope

Reuse the existing local STDIO MCP server and installed desktop executor. No separate CLI, database, authentication flow, approval queue or runtime. Pod relocation, new remote access and automatic E2E/layout jobs are excluded. Existing Claude configuration and the IURIO monitor must be preserved.

Dependencies installed with pnpm install --frozen-lockfile.

The browser API currently uses its own DDISA session and Origin checks, with no Pods CLI. Building CLI authentication would duplicate setup. The MCP launcher already reaches the private desktop socket, which dispatches through the central writer. Current MCP lacks online inventory, hides run results/errors and generates a fresh action ID per call. The central client already provides inventory/read/submit/operation with the needed authorization, online gates, revisions and durable receipts.

Example user flow

“List my Pods and show which are online.” → inventory with availability.

“Create a test Pod and run its script once.” → current revision, one command ID, applied receipt and run result.

“Retry the same command.” → the original receipt and run ID, without a second effect.
