Report templates for Test Runs and Plans

Agents publish test evidence and plans by filling one JSON file, running one render script and publishing the resulting HTML with ape-reports. After all producers have moved, ape-testruns upload and ape-plans are removed, and every instruction names only the new way.

Issue: patrick/monorepo issue 1437

Context: Reports (report.openape.ai) is the read-only home for single-HTML documents since the October 6 redesign (issue 1433). Publishing is already one command, ape-reports publish file.html --key KEY. What is missing is a consistent, well-designed way to produce the two most common documents, test evidence and plans, without hand-writing HTML each time.

Today: packages/ape-testruns/examples/ contains testrun.html, plan.html and a 12-line render-plan.mjs that only replaces a title and a description. ape-reports docs templates still says templates are local and optional.

Owner decisions (October 6, 2026)

  1. Templates are files plus a render script. The ape-reports commands stay as they are; the script writes one HTML file that ape-reports preview/publish then handle.
  2. Plans take structured JSON (goal, decisions, milestones with acceptance criteria, risks, verification, progress), not Markdown.
  3. Test Runs take the existing ape-testruns manifest (tests, steps, screenshot paths) unchanged; local screenshots are embedded.
  4. The old CLIs are deprecated and then removed.

Milestones

M1 · Template design prototypes

Two rendered prototypes from realistic sample JSON, approved by the owner before code is final.

  • Test Run: summary verdict (passed/failed/skipped counts, duration, project, tested commit), checks table, tests with steps, captions, errors and embedded screenshots in a window frame; failed items first-class.
  • Plan: status line, lead, owner decisions, open decisions, milestone cards with goal, steps, acceptance criteria and proof, non-goals, risks, verification commands, progress log, links.
  • Both: own document design (documents keep their design inside Reports), light and dark, readable at 375 px with no horizontal overflow (lesson from issue 1435), print-friendly, no external resources.

Proof: both prototypes published privately under Plans; screenshots at 1440/375 px light/dark; owner approval recorded here.

M2 · Render script and templates

ape-report-render produces one valid single-HTML file per template.

  • Location: packages/ape-testruns/templates/ (test-run.html, plan.html) and src/render.ts, built into the package and published with it.
  • Input validation with precise errors: the test-run manifest uses the existing validation rules; the plan schema is versioned ("schema": "openape.plan/1") and documented.
  • Text is escaped; Markdown in manifest summaries, descriptions, captions and errors is rendered with the existing marked/sanitize-html allowlist. Screenshots are embedded as data URIs; files above 8 MiB or a document above 20 MiB fail with a clear message.
  • Embedded script#openape-report sets category (Test Runs / Plans), tags and metadata (tests.result, tests.commit, plans.status).
  • Remove examples/render-plan.mjs; examples become the sample inputs.

Proof: unit tests render the samples and pass inspectHtml from @openape/report-contracts (the server's own validation), escape hostile input and enforce limits; ape-reports preview out.html --check exits 0 for both.

M3 · Team commands in ape-reports (if D1 approved)

Everything ape-plans does for teams works through ape-reports.

  • Port teams create|invite|accept|members|archive to the Reports team API; same version checks and outputs; generated CLI reference updated.

Proof: existing reports CLI tests extended; one real round trip on a synthetic team in the E2E harness.

M6 · Deprecation and removal

The old CLIs and their write paths are gone; all links still open.

  • Release with deprecation notices (ape-testruns upload, ape-plans), then npm deprecate for @openape/ape-plans after owner confirmation.
  • After D4: remove packages/ape-plans, the upload command, and (D3) the server write paths; keep read routes, old slugs, migrated plan URLs and redirects; update workspace map and dependency graph.

Proof: old /r/SLUG and migrated plan links return 200 for authorized readers; removed write routes return 404/410; pnpm check:ci green; tested deployment with rollback tag.

Non-goals

  • No template registry, server-side rendering or template upload to Reports.
  • No change to the reading surface of Reports or to the trust decision for active HTML.
  • No conversion of existing immutable plan or test-run versions; a migrated plan moves to JSON on its next edit.
  • No notification features.
