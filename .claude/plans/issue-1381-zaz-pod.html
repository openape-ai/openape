zaz task queue served by a scheduled OpenApe Pod

zaz.delta-mind.at gets its LLM answers again. A Pod checks the queue every 60 seconds without a model call, claims only claimable tasks, and answers them. It returns each result to zaz exactly once.

Purpose and scope

The launchd worker at.openape.worker was stopped on purpose and stays disabled. It served zaz, the troop cockpit and mail/invoice tasks. Only zaz moves to Pods. zaz health (/api/agent/health) reports 503 because nobody polls. The IURIO monitor Pod 98c32f74-ffaf-4628-bd41-95cea821572f (900 s schedule, rev 2, checkpoint 38, five completed effect receipts) must remain unchanged. Automatic E2E/layout jobs stay off.

Verified starting point

zaz protocol

@openape/sp-tasks 0.1.0. POST /api/agent/tasks/next leases the oldest submitted or expired task (300 s lease) and returns {task}. POST /resolve requires the matching assignee and a live lease. A terminal resolve clears both, so a repeated terminal resolve is refused with 409 and no duplicate artifact is possible. Task data: systemPrompt, userMessage, model (gpt-5.5). Synchronous callers wait 280 s; extraction is decoupled.

Authentication

zaz verifies an id.openape.ai JWT and an allowlisted sub. The existing agent key op-delta-mind-cb6bf26a+patrick+hofmann_eco@id.openape.ai is allowlisted. Its standard agent token (8 h) returned 200 at next on 2026-09-24. The old operator delegation rotates its grant ID monthly and is therefore unsuitable.

Production data

No open tasks. 142 llm tasks with at most 8.5 KB results. Extractions have history up to 54 KB and results up to 40 KB, and took up to 15 min on Sonnet. zaz runs branch feature/monatssoll 7002422 (deployed 2026-09-11 13:09); main is 10 commits behind.

Pods gaps (main 967038a5): Every POST reply is stored in the centrally replicated effect_ledger, so an IdP token reply would leak there. Other limits:
  • request body ≤16 000 characters
  • response ≤20 000 bytes
  • ledger input and result ≤32 KB
  • agent.run 120 s and gpt-5.5 fixed
  • run budget 300 s, including agent time
Every POST is an effect: a network failure or 4xx marks it unknown and blocks the Pod until owner reconciliation.

Owner decisions (2026-09-24)

Implement the Pods and zaz changes. Raise the limits instead of rejecting large extractions.

Milestone 1 — Pods runtime (monorepo, issue 1381)

  • DDISA agent authentication for HTTP resources. assignHttp accepts optional authentication {type:"ddisaAgent", credential, subject, issuer}. For such origins, main reads the assigned key secret, signs an EdDSA client assertion, calls issuer/token itself and caches the token until shortly before expiry. It then injects Authorization. Script-supplied Authorization is refused for that resource. The token never reaches the script, logs, run events or ledger.
  • Digest receipts. The HTTP request option receipt:"digest" stores only status, SHA-256 and byte length in the ledger. The live reply is returned in full; a replay returns the digest receipt with an empty body. The default stays the full receipt, so IURIO/Telegram are unchanged.
  • Limits.
    • Request body 64 KiB and response body 128 KiB, within the 256 KiB frames.
    • The ledger stores only a hash of the input, so its input bound rises accordingly.
    • agent.run gets optional timeoutSeconds (30–900, default 120).
    • Time spent in agent.run does not consume the script run budget; the agent call has its own bound.
  • Update runtime help, the MCP command schema and the handbook. Add focused regressions to the existing unit suites: token injection/refusal/caching, digest receipt/replay, larger bodies, agent timeout, and run budget.

Acceptance: full pnpm lint, pnpm typecheck, Pods build and focused unit tests; exact-source external CI; native PR merge.

Milestone 2 — zaz pending check

From the deployed feature/monatssoll, branch feature/agent-pending adds authenticated GET /api/agent/tasks/pending. It reuses resolveServiceAgent and the claimable predicate of leaseNextTask, returns {pending}, and records the poll so health reflects a live consumer. Deploy with deploy/README.md, verify health and the endpoint, and open a Forgejo PR into feature/monatssoll.

Milestone 3 — installation

Run pnpm check:ci from clean main, then the signed/notarized internal package and mounted-DMG check. Wait for idle IURIO, take a paired app/profile backup, and record IURIO identity, schedule, checkpoint and receipts. Replace the app, restart it on the same profile, verify central reconnection and the unchanged IURIO state, and leave the app open.

Milestone 4 — Pods via MCP

Import the op-delta-mind key as Pod secret zaz_agent_key by file path (never by value). Assign https://zaz.delta-mind.at GET/POST with ddisaAgent authentication. Script per run:

  1. GET pending. At 0, finish with zero model calls.
  2. Otherwise POST next with digest receipt and key zaz:claim:<runId>. Checkpoint the leased task ID and delivery count.
  3. agent.run with systemPrompt + untrusted userMessage and tools:[]. Strip fences as the old clean.py did.
  4. POST resolve completed (or failed with a reason) with key zaz:resolve:<taskId>:<delivery> and a digest receipt.
  5. Commit the checkpoint and return a summary.

A separate test Pod runs the same script against a controlled synthetic task inserted in zaz. Then the zaz Pod is activated with a 60 s interval.

Verification

  1. An empty queue makes zero agent.run calls (run events).
  2. A controlled test task is completed and its artifact is visible in zaz.
  3. Repeating a run or replaying the same key sends no second resolve; zaz has one artifact.
  4. Status and results are visible in the browser (pods.openape.ai/workspace) and on the desktop.
  5. Natural scheduled runs follow and zaz health returns 200.

Rollback

Pause the zaz Pod or disable its schedule. The zaz endpoint is additive; redeploy the previous release symlink. For Pods, reinstall the previous signed app (67c10b97 DMG) only if central data is compatible. Never restore an older profile over newer central writes or receipts.

Decision log

MCP-only Pod setup with no database edits. A GET pending check avoids per-minute effect receipts and blocking on transient claim errors. Runtime-injected DDISA authentication keeps tokens out of centrally replicated receipts. Digest receipts avoid a second copy of zaz content in Pods and avoid the 32 KB ledger limit. op-delta-mind is chosen over the rotating operator delegation. gpt-5.5 matches the model requested by zaz tasks.
