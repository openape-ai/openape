<h1>Pods infrastructure outage recovery</h1>
<p class="lead">A short identity-provider or service outage must pause safe work and recover automatically. It must not permanently block a scheduled Pod or repeat an uncertain external action.</p>
<div class="callout callout-info"><strong>Status:</strong> Investigation and live recovery completed. Implementation approved by the owner and implemented; review and signed installation in progress. This change spans authorization, run lifecycle, persistence and packaging; estimated implementation and acceptance exceeds one hour.</div>
<h2>Purpose and scope</h2>
<p>The zaz Service-Agent stopped after its first HTTP request encountered a permission-service 503 on September 26 at 14:28:48 UTC. Host logs show the owner IdP container was being replaced then; the replacement listened at 14:28:51. The run had approved runtime authority, and its HTTP grant is still approved. RunStore.finish marks all uncompleted inputs blocked; Scheduler.drain excludes Pods with any blocked input. No retry occurs after the infrastructure recovers.</p>
<p>Cover transient DNS/network failures, timeouts, rate limiting and temporary service responses in authorization and assigned HTTP reads. Retain explicit denial, revocation, identity mismatch, validation failure and uncertain external-effect recovery. Do not change grant semantics, widen permissions, silently approve grants, restart other Pods or redesign deployment hosting.</p>

<h2>Milestone 2: automatic recovery with backoff</h2>
<p>Use cancellation-aware exponential backoff, beginning at two seconds and capped at one minute, honoring bounded Retry-After. Retry the same safe operation inside a running script so prior script steps and completed deliveries are not rerun. Record retry state and the next attempt for visible diagnosis, and exclude infrastructure waiting from the script computation budget. Avoid unbounded rapid polling or invisible hangs.</p>
<p>When a run must stop, persist a delayed retry only if re-entry is provably safe: no uncertain or completed external effect from that attempt, no committed progress that would be replayed, unchanged script/resource binding and verified process cleanup. Longer infrastructure outages remain retryable with a bounded cadence instead of a permanent blocked input; release run capacity between delayed attempts. Preserve accepted input IDs and retry metadata across desktop restart. Do not automatically clear historical blocks by matching their error strings. For execution-authority monitoring, retain fail-closed execution: lack of authority evidence must never permit an external operation.</p>

<h2>Discoveries and decisions</h2>
<p>The mandatory pre-commit audit found two newly indexed high-severity fast-uri advisories in the existing lockfile (GHSA-qw65-cvwx-89v3 and GHSA-58mr-gqgx-xq4g). The release prerequisite is a targeted 4.1.3 → 4.1.4 pin; 4.1.4 was published September 2 and is outside the seven-day quarantine. Remove its obsolete quarantine exception, preserve unrelated lockfile resolutions and rerun the complete mandatory contract. No audit bypass.</p>
<p>Broker-network.ts normalizes DNS/connection failures, timeout, upstream 5xx and malformed broker metadata into 503. HTTP status alone cannot prove whether an external mutation happened. The original 503 response body was not retained, so the exact internal broker request cannot be reconstructed; the deployment outage is independently corroborated by matching host timestamps.</p>
<p>Implementation additionally passes an explicit transport and fetched JWKS into the existing assigned-command verifier so JWKS and grant-consume outages preserve trusted transport metadata. Identity, signature, issuer, adapter and grant validation remain mandatory. Ambiguous grant creation and already launched arbitrary tools still require review; no blind grant creation or command replay.</p><p>Durable retries are deliberately restricted to attempts before the script process starts, even without ledger effects, because arbitrary local writes cannot safely be replayed. A pause stops durable retries; pausing an active infrastructure wait cancels that run. Already executed scripts are never automatically restarted.</p><p>Prefer retrying the current safe operation over restarting arbitrary scripts. Keep uncertain effects blocked. Do not alter standing-grant or fail-closed authorization semantics to improve availability.</p>
