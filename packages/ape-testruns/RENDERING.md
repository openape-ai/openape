# Local report rendering

`ape-report-render` reads UTF-8 JSON (maximum 1 MiB) and writes one self-contained
HTML file. It uses no network or authentication. Errors exit 2 before writing;
replacing an existing file requires `--overwrite`. Publication is a separate step.

## Canonical authoring files

- `schemas/report.schema.json`: Draft 2020-12 structural contract, shipped offline.
- `templates/test-run.html` and `templates/plan.html`: reviewed document structure.
- `templates/document.css`: shared responsive light/dark/print presentation.
- `examples/versioned/`: small, explicitly illustrative authoring examples.

Use `openape.test-run/1` and `openape.plan/2` for new documents. TypeScript types in
`src/report-types.ts` are generated by `node scripts/report-contract-types.mjs`;
the existing Vitest suite checks schema/type freshness. Ajv and ajv-formats validate
structure, dates and unknown properties; semantic validation additionally enforces
references, outcome consistency, credential-free HTTPS, paths and evidence integrity.
The schema alone is not the complete validator.

## Test Runs: `openape.test-run/1`

Required: `schema`, `title`, `purpose` (verification/characterization/reference),
and nonempty `tests`. Each check requires a unique `id`, `title`, and `status`:
passed/failed/skipped/blocked. Skipped and blocked require `reason`; failed requires
`error` or `observed`. Optional description, expected, observed, error and steps
preserve the actual finding. Steps have title, optional status/caption and evidenceIds/
commandIds. Incomplete steps need an explanatory caption; a passed parent cannot
contain a failed or incomplete step. An expected refusal that occurred is passed.

Optional context: project, language, sample, summary, series, startedAt/finishedAt,
scope.covered/excluded, targets, commands, evidence, limitations, nextStep,
assessment, sections, links and provenance. Series is a label, not a server ID.
Timestamp values must include their timezone; an end cannot precede its start.
Elapsed duration is the run interval, never a sum of possibly parallel commands.

Commands require id, command and outcome (exited/timed-out/interrupted/not-started).
Only exited requires/allows exitCode. Optional cwd, targetId, timestamps, durationMs,
expectedExitCodes, summary and evidenceIds record the observation. Exit codes do
not determine check status: an expected audit exit 1 can support a passed check.
Do not split a compound command string into invented execution receipts.

Assessment requires outcome (acceptable/action-required/inconclusive/not-assessed)
and summary; optional evidenceIds cite supporting observations. Passing checks
can coexist with an adverse assessment. Missing assessment means not recorded.
Counts derive from checks only: failed takes precedence over incomplete (skipped
or blocked), then passed. Sample/reference documents omit tests.result and
any tests.commit metadata. Other documents emit a commit only when every check
explicitly names a clean source target with the same known commit. Missing/mixed
or dirty targets retain their context without claiming one tested commit.

## Shared evidence and targets

Targets require id, label and kind (source/build/deployment/device/prototype/other).
Optional commit, dirty, changesDigest, artifactDigest, version, environment, url
and notes identify the exact subject. Dirty targets require changesDigest. Use a
full Git SHA for new evidence; historical 7–64 hex abbreviations remain accepted.
Describe what the changes digest hashes. There is no implicit target inheritance.

Evidence requires a unique id, title, kind and role. Reference IDs must resolve;
IDs are unique in their own namespace. Unreferenced evidence remains visible in
an appendix without silently verifying a check.

| Kind | Content | Roles |
| --- | --- | --- |
| image | relative path, caption; optional targetId/capturedAt/viewport/theme/inspection | evidence, reference, mockup |
| text | exactly one relative path or inline text; optional targetId/language | evidence, reference |
| link | credential-free absolute HTTPS url; optional targetId/version/digest | evidence, reference, mockup |

Images are PNG/JPEG/GIF/WebP, at most 8 MiB each, with matching signature and
extension. Text files must be valid UTF-8 and at most 1 MiB. Paths must remain
beneath the input directory after symlink resolution; absolute paths, traversal
and controls are rejected. The final HTML is at most 20 MiB. No silent truncation,
resizing or remote fetching occurs. A URL remains an external reference, even
when its recorded version/digest is shown. Mockups never count as check images.
Actual screenshots of synthetic test fixtures are evidence, not sample outcomes.

Inspection is an author's attestation: by, at (with timezone), result
(matches/differs/inconclusive), notes and the exact image SHA-256 digest. Rendering
rehashes the file and rejects changed bytes. It does not inspect the image or
verify the inspector's identity. Missing attestations are displayed per image.
Only claim inspection after personally viewing the exact captured bytes.

## Plans: `openape.plan/2`

Required: schema, title, goal, status (draft/active/done/archived), milestones.
Each milestone requires id, title, goal, status (planned/active/done/blocked),
and nonempty acceptance criteria. Optional steps, proof, evidenceIds, rollback
and blocker retain execution detail. Blocked milestones require blocker.

Optional: project, owner, date, context, revision, decisions, scope, nonGoals,
risks, verification, changelog, approval, completion, handoff and all shared
language/sample/targets/evidence/sections/links/provenance fields. See the schema
for exact nested fields. Completion requires result
(achieved/partial/not-achieved/not-assessed) and summary; evidenceIds are optional.
Done tracks concluded work, not success. Done with unfinished milestones needs
an explicit completion summary. Rollback summary derives from milestones.

Approval requires by, date and reference containing the real owner's decision.
Optional scope states conditions. Optional target identifies revision, a frozen
sourceDigest, or url plus version. A matching local proposal revision records a
bound statement, never verified identity. Another revision does not cover the
current one. Unbound, digest-only or external-artifact decisions remain explicitly
unverified for current-source equivalence. A matching revision combined with an
unresolved external reference remains conservative, not automatically approved.
Contradictory digest/version references fail when local provenance resolves them.

Proposal revision is distinct from the Reports publication version. Increase it
for substantive scope, goal, acceptance, decision or permission-boundary changes;
progress/proof updates may retain it if those boundaries remain unchanged. The
renderer never infers approval, semantic equivalence or permission to publish.
Never put the source's own digest inside the source being hashed.

## Narrative and compatibility

Sections require id, title and Markdown body; placement is before-details or
(default) after-details, relative to checks/milestones. Use meaningful sections
for long architecture, operational receipts and handoff. Fields are bounded at
20,000 characters (titles 300); lists at 200 items (steps 100). Split long content
at meaningful boundaries, preserving exact source links and digests.

Markdown supports sanitized tables and code. Raw HTML is escaped; Markdown images
become text references, not remote requests. Source JSON is embedded inertly,
with script-closing characters escaped. Unknown fields are rejected recursively.

Explicit compatibility readers retain unversioned RunManifest and openape.plan/1
inputs and their original presentation. Old immutable outputs are never rewritten.
Legacy context flags --commit/--command/--environment/--next-step remain supported;
the root commit is contextual and no longer claims tests.commit. Legacy manifests
show a format-gap notice for absent skip reasons and image attestations. Their
original image bytes remain embedded, without invented inspection claims. Plan/1
approval wording remains unbound. New documents must use versioned examples.
Context flags with a versioned Test Run are rejected rather than overriding input.

There is no automatic lossless import of arbitrary historical HTML/Markdown.
Map its sections/evidence explicitly, retain original files, and cite frozen
provenance. Do not discard scripts, diagrams or domain context and claim fidelity.

## Receipt and publication

`--json` returns rendererVersion, templateDigest (HTML template bytes followed by
shared CSS bytes), sourceFileDigest (exact input bytes), resolvedEvidenceDigests
(embedded image/text bytes), htmlDigest, output, bytes and published:false. Digests
use lowercase SHA-256. Linked external content is not hashed or fetched. The
receipt is separate from the HTML, avoiding a self-referential digest.

```sh
ape-report-render test-run run.json verification.html --json
ape-report-render plan plan.json plan.html --json
ape-reports preview plan.html --check
ape-reports publish plan.html --category Plans --key plan-v1
ape-reports show DOCUMENT_ID --json
# Preserve concurrent authors' edits before changing the local source.
ape-report-render plan plan.json plan.html --overwrite
ape-reports publish plan.html --document DOCUMENT_ID --expected-version 1 --key plan-v2
```

Publication defaults to private, permanent retention. Category/status metadata
never grants access or owner approval. Document ID, audience, team, expiry,
idempotency key and expected publication version belong to publication state,
not authoring input. Reuse key and bytes after an unknown outcome; a new intentional
version gets a new key. Verify the returned authenticated document and category.
