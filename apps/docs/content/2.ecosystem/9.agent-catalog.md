# Agent Catalog

The **agent catalog** is the source of truth for the personas troop can add to an org chart and spawn as working agents.

In this repo, the generated catalog lives in `apps/openape-troop/server/utils/persona-catalog.ts`. troop exposes the public fields through `GET /api/personas`.

Each catalog entry defines:

- the persona key and title
- the structural org role it occupies (`ceo`, `teamlead`, `specialist`, `sanierer`, `other`)
- the picker category and icon
- a one-line summary
- whether the persona works on code
- the pinned recipe troop deploys for that persona
- the default recipe parameters troop injects at spawn time

## What troop uses it for

When you add a member in troop or openape-org, the catalog drives the persona picker. When you later spawn that member, troop uses the same entry to select the pinned recipe and inject the default recipe parameters.

This keeps three things aligned from one source:

1. the title and icon the owner sees
2. the org-chart role the member occupies
3. the recipe the spawned agent actually runs

## Building a company from the catalog

A company is assembled by adding members with one of these persona keys. troop stores the selected persona on the member record, derives the chart role from the catalog, and later spawns the matching recipe with the catalog's default parameters.

Typical flow:

1. Create an org.
2. Add members from the persona picker.
3. Set reporting lines in the org chart.
4. Spawn the members that should start working.
5. Assign tasks according to each persona's mandate.

If you need a placeholder org node without a predefined persona, the UI also supports a custom role without a catalog entry. That member has a structural role, but no pinned recipe to spawn from.

## API shape

`GET /api/personas` returns category metadata plus the public persona fields troop needs in the UI:

```json
{
  "categories": [
    { "key": "leadership", "label": "Leadership & Coordination" }
  ],
  "personas": [
    {
      "key": "backend-engineer",
      "title": "Backend Engineer",
      "role": "specialist",
      "category": "engineering",
      "icon": "i-lucide-server",
      "summary": "Implements server-side features, APIs and data access against assigned issues.",
      "coding": true
    }
  ]
}
```

The pinned recipe reference and default recipe parameters stay server-side and are applied when troop handles a spawn request.

## Source of truth

Do not maintain this list by hand in multiple places. Update the underlying agent catalog source, regenerate `persona-catalog.ts`, and let the docs describe the generated result.
